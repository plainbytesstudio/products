1What this app is for

1.1 True redaction vs. draw-over preview

These two approaches mean very different things for compliance and security:

AspectDraw-over preview ("black bar")True redaction
Inside the PDF Text, vectors, or images can still be in the file — often just covered by another graphic. Matching content is removed from the content stream so it isn't recoverable through normal parsing.
Copy / search Depending on the tool, "hidden" text might still copy out. Selectable text no longer contains the sensitive strings (verify on your exported file).
Best for On-screen reading or quick cover-ups. Sharing externally, archiving, audits, diligence — anywhere content must be gone for good.

Key principle

PlainBytes Redactor is built around true redaction. Use Confirm so you're clear which areas are actually removed at export.

1.2 What we mean by "local and offline"

  • Work stays on this PC — opening the PDF, rule matching, writing the redacted file, and validation all run locally.
  • No document upload for redaction — the product isn't designed to ship your files to the cloud as part of the redaction pipeline.
  • Separate from Help / updates — opening Help or Check for updates may launch your browser or the Microsoft Store. That's unrelated to keeping the redaction path offline.

1.3 When it's a good fit

  • Workflows in legal, finance, healthcare, public sector, or audit where you want human review and a smaller blast radius for leaks.
  • You need to hand out a PDF but strip IDs, account numbers, contact details, and other identifying data.
  • You have many PDFs with the same layout — confirm once, then use Apply to multiple files to reuse the geometry (see Step G, §3 and §9).

2Core ideas

2.1 Redaction marks

Internally, each area you might redact is a redaction mark — a rectangle on a page plus metadata:

  • Page and rectangle — position and size in PDF coordinates.
  • State — Pending vs. Confirmed; only confirmed marks are removed when you export.
  • Source — Rules (patterns/regex) or manual selection.
  • Category and risk — used to filter, sort, and bulk-act in the audit list.

2.2 What "confirm" means — and why it's manual

  • Automation isn't the final say — rule matching can over-flag normal text or miss real sensitive bits.
  • Confirm = you're signing off — once confirmed, a mark is included in the export set.
  • Fits real-world review — lines up with two-person review and audit trails.

2.3 The batch baseline

  • There's no saved template file. Batch uses an in-memory geometric baseline built from confirmed marks on the current document.
  • For each queued PDF, the engine only stamps those rectangles — it does not re-run rule detection per file.
  • Works best for documents with the same layout and sensitive regions in the same place.

3End-to-end workflow

Walkthrough setup

In this example, a legal reviewer has an 8-page employee offboarding PDF to release externally. They need mobile numbers, partial bank-card snippets, and personal email addresses removed. The file is a real electronic PDF with selectable text (not a flat scan).

AOpen the document

Drag, drop, or open

Use Open or drag-and-drop to load the PDF (common image formats are also supported). Everything — preview, detection, and marks — is tied to this one source file.

BRegion & scenario

Pick region and scenario in the rules hub

Open Rules, choose a region (country/area), then a business scenario (general, financial, etc.). The effective rule set changes with both — picking the wrong scenario can leave useful rules off.

CRun detection

Let the document model run

Under scan policy, click Start detection and let the full pass finish. This turns rule hits into a list of pending marks. Re-run detection any time you change region, scenario, or rules.

DReview audit list

Confirm what must go

Walk items one by one or use filters. Export only honors confirmed marks — this step is what keeps you from deleting the wrong thing or leaving something behind.

EManual boxes

Catch anything rules missed

Drag rectangles on the left-hand preview over anything rules didn't catch. Manual boxes are your safety net — auto detection won't catch everything.

FExport

Get your redacted copy

Choose Export redacted, pick a save location, and read the completion summary. If it flags warnings, open the exported PDF and spot-check.

GApply to many (optional)

Reuse confirmed positions on similar files

Use Apply to multiple files to build a normalized baseline and open batch redaction. Add PDFs with matching layout, set an output folder, and run.

Important

This isn't a reusable named template on disk — the baseline comes from this confirmed document only, and batch doesn't re-run rule detection per file.

4Main window tour

4.1 Preview (left)

Renders each page of the PDF or image. Auto and manual pending areas show as highlights; clicking a region often toggles confirm state together with the list. Click-drag on the preview adds a rectangular mark.

4.2 Scan policy panel

Entry point for running detection, aligned with region, scenario, and rule sets from the hub. Kept separate from the audit list to reduce confusion between "scan the doc" and "work the list."

4.3 Selection appearance

Tweak how manual selections look — border, fill, custom colors — so boxes stay visible on noisy backgrounds. This is visual help only; redaction still depends on confirmation and export.

4.4 Audit trail list

Aggregated sensitive hits for the open document, with filters by category and risk, plus per-row or bulk confirm/clear actions. Selecting a row scrolls and highlights the matching page.

4.5 Toolbar buttons

  • Open — pick a local PDF or supported image.
  • Close document — closes the current file.
  • Previous / Next page — navigate the preview.
  • Rules — opens the rules hub.
  • Batch — opens batch redaction.
  • Export redacted — available once marks are confirmed.
  • More (⋯) — language, Help, feedback, updates, About.

5Rules hub

5.1 Region and business scenario

  • Region — drives which built-in patterns apply (ID formats, phone rules, etc.).
  • Business scenario — narrows or emphasizes rule bundles (general, financial, healthcare, legal/government).
  • Together — set region first, then scenario; re-run detection after changes.

5.2 Built-in vs. custom rules

  • Built-in — shipped with the app, grouped by category, fully offline.
  • Custom — your label plus a pattern (substring or .NET regex), useful for internal codes the built-ins don't know.

5.3 When to adjust rules

  • Too much noise — disable overly broad rules or pick a closer scenario.
  • Recurring pattern — add a custom rule to cut down manual boxing.
  • Config drift — Restore defaults clears local overrides.

6Audit sidebar

6.1 Why confirmation works this way

A row often groups multiple occurrences of the same sensitive type across pages. Pending keeps "model guess" separate from "human decision" — the export engine only consumes confirmed marks, by design.

6.2 Filters and bulk confirm

Filter by category or risk to tackle high-priority items first. Bulk actions flip confirm state for everything visible under the current filter — check the active filter before a bulk action.

6.3 Risk levels

Levels (critical, high, suspicious, medium, low) help you sort and filter so the riskiest hits surface first. They are not a mandate to confirm — you still decide.

7Manual selections

7.1 When to draw your own boxes

  • Rules missed something you know must go.
  • Hits are fragmented or misaligned — clear the bad row and draw a tighter box.
  • Scan-only content handled as imagery (see FAQ).

7.2 Working with auto-detected marks

A practical order: run detection → clear obvious false positives → add manual boxes for real misses → skim the preview page by page. Manual and automatic marks are treated identically at export — what matters is whether they're confirmed.

8Export

8.1 Pre-export checklist

  • This is the file you mean to release (page count, attachments checked).
  • Everything that should be redacted is confirmed; anything that must stay is cleared.
  • You've eyeballed key pages in preview, including manually boxed sections.
  • Export writes a new file and typically doesn't overwrite the original.

8.2 Why strip metadata

Beyond page content, PDFs carry author, producer, timestamps, XMP, and more. Redacting body text but leaving metadata can still leak internal accounts or edit history. Leave metadata cleanup on for anything leaving the building.

8.3 Reading the summary

  • Does the count of physically removed items feel right?
  • Does it confirm metadata was cleared?
  • If you see text validation warnings, open the exported PDF and check manually.

9Batch processing

9.1 What batch mode actually does

Each queued PDF follows a stamp-only path: normalized rectangles map to absolute coordinates per page, marks are created, content is physically removed, and metadata can optionally be cleared. It does not re-run rule detection per file.

9.2 Good use cases

  • Many PDFs from one system with the same layout and sensitive regions in the same relative positions.
  • You've already confirmed on one exemplar and want to skip repeating the work.

9.3 Things to watch

  • No saved template file — closing the batch window drops the in-memory baseline.
  • Small layout shifts can mean missed or wrong regions — spot-check first outputs.
  • Turn on clear properties and hidden data for external sharing.
  • If Apply to multiple files is greyed out, your license tier may limit batch.

10FAQ

Q.Why are there so many false positives?

Rule matching leans on patterns and heuristics — strings that look sensitive, place names colliding with person names, table fragments. Tuning the scenario, disabling a noisy rule, or clearing confirmation usually gets it under control.

Q.What about scanned PDFs?

If the PDF is effectively a page image with no real text layer, rule detection has less to work with — you'll lean more on manual boxes. It helps to know upfront whether you're dealing with a born-digital PDF or a scan.

Q.Can I redact images? Why isn't text in photos recognized?

Yes — common image formats open like a document. This version doesn't ship OCR, so text in photos isn't selectable and rule-based detection barely applies. Redact sensitive areas by drawing boxes instead.

Q.How do I sanity-check an export?

In any PDF reader, try select-all and search for strings you know were sensitive. Visually scan headers, footers, and footnotes. Read the export validation summary, and for high-stakes documents, layer additional review.
